# 参考库管理：专项入口前端交接说明

更新日期：2026-10-24。

本文用于前后端同步参考库管理页面的业务设计和当前源码接口契约。专项查询、专项上传及分类归属确认已在源码中实现；2026-10-24 已完成一轮本地真实 HTTP 上传及读回测试，覆盖范围见第 11 节。**不代表目标环境已部署、已完成前端联调或线上验证。**

接口的完整字段约束见[参考序列库管理接口说明](./reference-library-management-guide.md)；创建任务参数见[病毒流水线创建说明](./virus-pipeline-creation-guide.md)。接入前仍需确认部署环境已经使用支持本文新增字段的版本。

## 1. 背景与最终页面目标

目前创建普通病毒／新冠流水线时，用户选择分析专项（目标 taxId），后端通过成员映射找到对应的参考序列。用户不必选择具体 accession，流水线仍负责最终参考选择。

参考库已支持上传追加、查看、启用和禁用，也支持通过专项上下文查询和上传。前端管理页面按专项组织：

```text
选择专项
  → 查看后端归集的参考序列
  → 查看详情、启用／禁用参考，或上传新参考
```

**管理对象始终是具体参考记录。专项只是查询和组织页面的入口，不是另建一套参考库。**

- 本期页面仅管理病毒参考，不提供病毒／细菌类别选择框，也不新增细菌参考管理入口。上传固定 `orgType=0`；管理列表显式传 `orgType=0`。后端通用接口仍保留 `1=细菌` 的兼容能力，不等于本期要求开发细菌页面。
- 同一条参考可出现在多个专项中，不复制文件或参考记录。
- 不增加成员分类级别的启停开关；不提供“启用整个 member”的配置。
- 参考启停是全局配置，同一条参考在其他专项中的状态也随之改变。
- 创建某次任务时的勾选属于任务参数，不应调用全局启停接口。
- 本期沿用已有专项列表，不新增专项创建、删除、改名或分类成员独立管理页面。

## 2. 名词与字段不要混用

| 名称 | 含义与存储 |
| --- | --- |
| 专项／分析目标 | 来自 `bio_pipeline_target`；现有下发字段为 `label`、`taxId`、`pipelineType` |
| `targetTaxId` | 管理请求字段，取所选专项的 `taxId`；与 `pipelineType` 一起标识专项上下文 |
| `memberTaxId` | 后端成员映射中的实际参考分类编号；没有成员级 `enabled` |
| 参考记录的 `taxId` | 参考实际所属分类；查询响应和上传中的 `taxId` 始终保持这个含义 |
| `referenceId` | 具体参考记录 ID，详情、启停、任务白名单使用它 |
| `orgType` | 参考类别：`0=病毒`、`1=细菌`；本期上传固定 `0`，不是 `pipelineType`，`0` 也不是未知值 |
| 参考的 `enabled` | `bio_reference_sequence.enabled`，全局允许／禁止进入新任务候选范围 |
| `enabledReferenceIds` | 某次任务允许使用的参考 ID 列表；不修改参考的全局状态 |

专项表自身的 `enabled` 控制选项是否下发，不是参考启停，也不是权限控制。专项查询和上传校验已登记的 `targetTaxId + pipelineType` 组合，不因目标选项被禁用而拒绝该组合；前端通常仍从启用选项列表选择。

前端无需维护专项到成员的映射字典，也不能根据名称自行推断成员关系。上传参考的实际 `taxId` 与专项目标可能相同，也可能不同，不能直接用专项 taxId 替代实际分类。

## 3. 当前源码能力与接入条件

这里的“已实现”指当前工作区代码具备能力，实际部署环境仍需确认版本。

| 能力 | 状态 |
| --- | --- |
| 获取专项选项 `GET /pipeline/virusTargets` | 已实现 |
| 按实际参考 taxId 查询、详情、全局启停、普通上传 | 已实现 |
| 创建任务时保存和校验 `enabledReferenceIds` | 已实现，仅普通病毒 `100`／新冠 `101` |
| 按专项展开全部成员后查询参考 | 已实现，复用现有查询接口 |
| 上传时接收专项上下文、校验分类归属 | 已实现，复用现有上传接口 |
| 用户确认后同时追加参考和专项成员关联 | 已实现，确认响应见第 7.2 节 |

查询 DTO 已接受 `targetTaxId`、`pipelineType`；上传字段白名单已接受这两个字段及 `confirmAddTaxonomyMember`。没有增加接口路径、成员级启停字段或数据表。`GET /pipeline/virusTargets` 与分页／单条参考响应结构不变。

**不要向旧部署发送新字段后就假定已经生效。** 旧版本可能忽略新字段，HTTP 200／上传成功不能证明完成了专项关联。确认部署版本并完成联调之前，应关闭专项范围查询和专项关联上传入口；不要静默退回全库查询后仍显示“当前专项参考”。目前没有专门的能力发现接口，接入开关需由部署版本／联调确认控制。

## 4. 页面交互

### 4.1 专项选择

复用 `GET /pipeline/virusTargets`，展示 `label`，保存该项的 `taxId` 与 `pipelineType`。此接口目前不返回成员列表或参考列表。

- 查询失败、空列表分别提示，不自行补造专项选项。
- 切换专项后清空旧列表、重置分页和临时勾选；晚到的旧请求不能覆盖新专项内容。
- 本次专项入口面向接口下发的普通病毒／新冠目标；不将污水专项 `102` 接入这套候选库配置。

### 4.2 参考列表

建议展示：accession、分类名称、实际 taxId、来源、长度、节段、全局启用状态，以及详情和启停操作。

管理列表显式传 `orgType=0`，默认包含启用和禁用的病毒参考，可提供“全部／已启用／已禁用”筛选。允许按实际 taxId 分组展示，但不必增加一个必须先选 member 的步骤，也不要把分组标题做成成员启停开关。“全部”表示当前病毒管理范围内的全部启用状态，不是包含细菌。

这里的管理筛选不能直接复用为任务白名单的完整候选来源：创建任务加载候选时不附加 `orgType`、实际 taxId 或 accession 等筛选，见第 8 节。

空列表只表示当前条件没有参考，不等于专项不存在或没有成员映射。页面可显示上传入口，但不能因为没有行就自动新增／替换成员映射。

### 4.3 全局启停

开关文案建议使用“允许参与分析”，并明确这是全局设置：

> 此操作会改变这条参考在后续候选加载中的可用状态，可能影响使用同一参考的其他专项。不会删除文件，也不会修改已有 Stage 保存的参考快照。

成功后可先使用服务端返回对象更新当前行，随后按当前专项、筛选和分页重新查询，刷新列表及 `total`。例如在“已启用”列表禁用一条后，该行应移出结果；末页变空时回退到仍有效的最后一页再查询，没有结果则回到 `start=0`。失败时恢复开关显示并重新读取状态，不保留未经确认的乐观状态。当前只有逐条启停，没有原子批量启停接口。

### 4.4 上传

从专项页面打开上传弹窗时，保留专项名称和上下文，同时要求填写参考实际 taxId，前端固定提交 `orgType=0`，无需用户选择类别。若提供病毒参考的全局上传入口，仍可不指定专项，但同样固定病毒类别，两者不能在界面上混为一谈。

一份文件对应一条参考库记录；多记录 FASTA 原样保留在同一条记录，不自动拆成多个候选。不同节段需要分别上传并填写相应元数据。上传是追加，不是替换已有 accession 的内容。

## 5. 已实现接口与响应

| 操作 | 接口 | 成功 `data` |
| --- | --- | --- |
| 专项列表 | `GET /pipeline/virusTargets` | `[{label, taxId, pipelineType}, ...]` |
| 参考查询 | `POST /referenceGenome/library/query` | `{total, start, pageSize, items}` |
| 参考详情 | `GET /referenceGenome/library/{referenceId}` | 单条参考对象 |
| 全局启停 | `POST /referenceGenome/library/{referenceId}/enabled` | 更新后的单条参考对象 |
| 上传追加 | `POST /referenceGenome/library/upload` | 新增的单条参考对象 |
| 下载文件（复用现有接口） | `GET /stageOutput/download?outputUrl=...` | 文件内容，不是 `Result` JSON |

业务响应包装为：

```json
{"status": 0, "data": {}, "failMsg": null}
```

前端同时判断 HTTP 状态与业务 `status`。`0` 成功；`1` 业务失败；`2` 内部错误；`3` 重复操作（上传通常为 accession 已存在）；`4` 参数或文件校验失败。当前参考管理接口内部错误通常 HTTP 500，其他业务结果通常 HTTP 200，绑定／格式错误可能 HTTP 400。网关或 HTTP 容器错误可能不是上述 JSON。

`failMsg` 按普通文本展示，不能作为 HTML 渲染。

当前部分后端错误提示仍含旧的类别编码文案，尚未随常量修正。前端以本文的 `0=病毒、1=细菌` 为准，不从 `failMsg` 推断枚举，也不要因旧提示把病毒改传为 `1`。上传与查询的缺省／非法参数仍按 HTTP 状态和业务 `status` 处理。

### 5.1 当前查询

```json
{
  "start": 0,
  "pageSize": 20,
  "taxId": 700002,
  "orgType": 0,
  "enabled": null
}
```

本文中的 `700001`、`700002`、`501` 等编号均为结构示例，不是可直接用于实际任务的分类或参考数据。

- `start` 是从 0 开始的行偏移量，不是页码；`pageSize` 默认 20，范围 1–100。
- `taxId` 始终精确筛选参考记录的实际分类；专项展开使用成对的 `targetTaxId`、`pipelineType`，见第 6 节。
- `enabled` 不传／`null` 查全部；`true` 仅启用；`false` 仅禁用。
- 接口可选字段 `orgType` 的编码为 `0=病毒、1=细菌`；本期管理列表固定传 `0`，另可传 `accession` 精确匹配，筛选条件共同生效。任务完整候选查询例外，见第 8 节。
- 固定按 `referenceId` 降序返回，不接受前端排序表达式。

单条参考对象目前包含：

```json
{
  "referenceId": 501,
  "accession": "LOCAL_DEMO_001",
  "sourceDb": "USER_UPLOAD",
  "taxId": 700002,
  "orgType": 0,
  "organismName": "示例分类名称",
  "genomeLength": 22,
  "segment": null,
  "completeness": null,
  "isAnnotated": false,
  "enabled": true,
  "fastaObjectName": "refseq/custom/example/reference.fna"
}
```

`fastaObjectName` 是对象键，不是 HTTP 下载链接；可能为 `null`。不要直接作为 `href` 或拼成服务器路径。文件下载复用现有接口，见第 5.4 节；分页和单条参考对象中没有成员列表、原始内部元数据或确认标识，专项上传的确认信息位于独立的响应包装中，见第 7.2 节。

### 5.2 当前启停

```http
POST /referenceGenome/library/501/enabled
Content-Type: application/json

{"enabled":false}
```

启用传 `true`，必须明确传布尔值。启用时后端检查文件可读性；禁用不删除文件。当前允许禁用最后一条参考，前端不能凭当前分页的条数判断整个专项是否还存在可用候选。

### 5.3 当前上传字段

使用 `multipart/form-data`，文件字段名为 `file`，其他字段分别作为表单字段，不是打包成一个 JSON part。使用浏览器 `FormData` 时不要手动设置 multipart `Content-Type`。

| 字段 | 要求 |
| --- | --- |
| `file` | 必填，非空 FASTA；支持 `.fasta/.fa/.fna` 及 `.gz/.gzip/.zip` |
| `taxId` | 必填，实际参考分类的正整数 ID |
| `orgType` | 必填；本期前端固定提交 `0`（病毒），不展示类别选择；后端通用接口兼容 `1`（细菌），不是 `pipelineType` |
| `accession` | 可选，最长 64，字母／数字开头，其后允许字母、数字、`.`、`_`、`:`、`-`；全库唯一 |
| `organismName` | 可选，最长 255 |
| `segment` | 可选，最长 64 |
| `completeness` | 可选，最长 32，描述文本，不是后端质量结论 |
| `enabled` | 可选，默认 `true`，也可导入为禁用状态 |
| `targetTaxId` | 可选，与 `pipelineType` 成对提供；专项上下文的目标 taxId |
| `pipelineType` | 可选，与 `targetTaxId` 成对提供；仅 `100`／`101`，必须是已登记组合，`101` 的目标固定为 `2697049` |
| `confirmAddTaxonomyMember` | 可选布尔值，默认 `false`；仅用户确认后重提时传 `true`，无专项上下文时不得传 `true` |

未填 accession 时后端生成本地 `CUSTOM_...` 标识。元数据不会从文件中自动推断或联网核实。不要把未填字段传成字符串 `"null"`。

`FormData` 中使用 `form.append("orgType", "0")`。`0` 是有效值，不能用 `if (!orgType)` 将它视为缺失或在构造请求时省略。

请使用单文件 ZIP，不把多个待导入参考打包成一份 ZIP。服务端参考导入默认上限 256 MiB，压缩流和解压后内容均受限，部署／网关可能有更严格限制。详细格式规则见现有接口说明。

### 5.4 文件下载

复用已有接口，不新增参考库专用下载路径：

```text
GET /stageOutput/download?outputUrl=<URL编码后的fastaObjectName>
```

- `fastaObjectName` 为 `null` 或空值时不显示可用下载按钮；有键也不保证文件仍存在，下载失败应明确提示。
- 使用前端现有 API base URL 和认证／会话配置；用 `URLSearchParams({outputUrl: fastaObjectName})` 或 `encodeURIComponent` 对参数编码一次，不硬编码本地测试端口，不拼接服务器磁盘路径。
- 成功返回文件字节，不是业务 `Result`。用现有下载处理方式保存文件；失败时检查 HTTP 状态、响应类型，并按 JSON 或非 JSON 错误显示提示，不把错误页面保存成 FASTA。
- 本轮普通 FASTA、gzip、ZIP 导入后均已通过该接口下载并验证内容一致；压缩输入保存的是解压后的 FASTA，因此下载文件不承诺保留原压缩包装。

## 6. 按专项查询参考

使用现有 `POST /referenceGenome/library/query`，以下是病毒管理列表的请求示例，不是任务完整候选查询示例：

```json
{
  "targetTaxId": 700001,
  "pipelineType": 100,
  "orgType": 0,
  "start": 0,
  "pageSize": 20,
  "enabled": null
}
```

- `targetTaxId` 与 `pipelineType` 要么都不传，要么成对提供；目标为正整数，仅支持 `100`／`101`，必须匹配已登记的专项组合，`101` 必须搭配 `2697049`。前端使用专项下发选项，不自建编号。
- 后端核对组合存在性，使用与任务候选加载相同的成员解析规则：有显式成员则仅使用这些成员，否则使用目标自身。对解析后的成员 `IN` 范围及其他全部筛选条件一起执行 `AND` 筛选、计数和分页。
- 原 `taxId` 仍表示实际参考分类；同时提供时，作为专项范围内的进一步精确筛选，不替代专项范围。
- 管理列表默认保留禁用记录；在管理页传 `enabled=true` 只表示查看已启用病毒参考，不自动等同于完整任务候选范围。
- 后端专项查询不隐式附加 `orgType`；本期病毒管理页显式传 `orgType=0`。任务白名单初始化则只传专项上下文、`enabled=true` 和分页，不附加 `orgType`，以保持与后端任务候选范围一致，见第 8 节。
- 无效专项或查询失败明确报错，不退回全库查询，不把失败显示成“无参考”。
- 不传专项上下文时，兼容原有精确 taxId／全库管理查询。
- 复用原有分页及单条参考响应，不返回成员列表，没有新增成员名称查询接口。

## 7. 专项上传与关联确认

在现有上传表单上增加：

| 字段 | 含义 |
| --- | --- |
| `targetTaxId` | 当前专项的目标 taxId |
| `pipelineType` | 当前专项的流水线类型，与 `targetTaxId` 一起提供 |
| `confirmAddTaxonomyMember` | 默认 `false`；仅在用户明确同意扩大专项分类范围后传 `true` |

原 `taxId` 继续保存参考实际分类，不能因为选择了专项就覆盖它。专项组合校验与查询相同，但专项上传还要求 `orgType=0`（病毒）。没有专项上下文时，维持原有全局上传行为，不隐式创建关联；此时传 `confirmAddTaxonomyMember=true` 是参数错误。

### 7.1 交互流程

1. 用户选择专项，填写参考实际 taxId 和上传元数据。
2. 如果实际 taxId 已在该专项有效范围内，正常上传，不重复登记关系。
3. 如果不在范围内且未确认，后端预检返回“需要确认加入专项分类范围”，不写入存储文件、参考或关联；事务内还会再次检查归属，发现预检后范围变化时也要求确认。
4. 前端保留表单和文件，展示下方影响说明；取消时不修改任何全局配置。
5. 只有用户确认后，才携带 `confirmAddTaxonomyMember=true` 重新提交。
6. 成功后刷新该专项的列表；筛选条件不包含新记录时，提示已导入并提供查看详情，不假装未成功。

确认提示建议：

> 此参考所属的 taxId 尚未纳入当前专项。加入后，该分类下的已有参考和后续新增参考都会进入专项查询范围，实际参与分析仍取决于参考自身的启用状态。这不是仅关联本次上传的文件。是否继续？

成员映射按目标 taxId 共享；若不同专项选项使用同一目标 taxId，此关联调整也会影响它们。不是给当前用户或单条任务建立私有关联。

### 7.2 机器可识别的确认响应

需要确认时，HTTP 为 `200`，业务 `status=1`，`data=null`：

```json
{
  "status": 1,
  "data": null,
  "failMsg": "该参考分类尚未纳入当前专项，请确认是否加入专项分类范围",
  "code": "REFERENCE_TARGET_MEMBERSHIP_CONFIRMATION_REQUIRED",
  "confirmation": {
    "targetTaxId": 700001,
    "pipelineType": 100,
    "taxId": 700002
  }
}
```

`failMsg` 是展示文本，示例文案不作为协议。前端应精确匹配 `code === "REFERENCE_TARGET_MEMBERSHIP_CONFIRMATION_REQUIRED"` 并核对 `confirmation` 与当前表单上下文，再展示确认弹窗；用户同意后才保留原文件和字段、增加 `confirmAddTaxonomyMember=true` 重提。切换专项或修改实际 taxId 后应重新确认。

此响应运行时使用 `ReferenceMembershipConfirmationResult` 子类扩展 `Result`；只有需要确认时增加 `code`、`confirmation`，普通成功、重复、参数错误等响应保持原结构。不要要求所有响应都携带这两个字段，不通过模糊匹配 `failMsg` 设置确认标志，也不要对任意失败统一确认重试。

### 7.3 后端一致性与失败边界

- 预检在存储文件前检查专项和归属；数据库事务内按目标 taxId 锁定该目标的全部目录行，再校验上下文和归属，避免同一 taxId 的不同流水线选项并发写入时丢失成员。
- 参考记录和新成员关联在同一个数据库事务中写入。文件不属于数据库事务；明确回滚时补偿清理本次文件，提交结果不明时保留文件并提示按 accession 核对。
- 原来没有成员映射时，默认范围是目标自身 taxId；首次确认加入其他分类时，保留自身范围，避免旧参考突然从专项消失。已有显式映射时不擅自补入自身。
- 重复／并发确认不能生成重复关联或丢失已有成员。
- accession 重复不会覆盖、重新分类或借此把已有记录补关联到专项；应先查询并核对原记录。
- 不新增成员级 `enabled`，不修改每条参考的数据结构，不自动新增专项下拉项。
- 未知专项、目录／成员读取失败或事务校验失败均报错，不以全库或另一范围继续上传。

## 8. 与创建任务的参考配置区分

参考库页面的启停是全局管理。创建任务页面的“自定义参考范围”是独立交互，字段已接入后端：

- 单个创建：`pipelineStageParameters.enabledReferenceIds`。
- 批量创建：`pipelines[i].pipelineParameters.enabledReferenceIds`，每项独立。
- 不传／`null`：启动时使用当前目标下全局启用的候选。
- 显式数组：必须非空，全部为不重复的正整数 ID；每条必须存在、全局启用且属于目标范围。任意一项无效则整体报错，不能悄悄删掉无效项或回退默认范围。
- 仅 `100`／`101` 支持；新冠 `101` 固定按目标 `2697049` 校验。
- 创建和启动都会校验显式列表；创建后全局状态变化可能使启动校验失败。
- 已保存的 Stage 快照不被后续全局启停／映射调整重写。

用户未自定义时不必加载全量参考，也不必提交列表。自定义时，使用 `targetTaxId + pipelineType + enabled=true` 查询并读取全部分页，不附加会缩小候选范围的 `taxId`、`orgType` 或 accession 条件；不能把当前分页的默认勾选当成全部候选。此处不要复制第 6 节管理列表固定的 `orgType=0` 筛选。需维护完整选择集合，确认数据来源完整后再提交；不以专项 taxId 的一次精确查询冒充完整候选列表。

## 9. 失败、重试与边界

- 上传返回重复 accession 时，原文件和记录不被覆盖；提供查询已有记录的入口，不自动生成另一个标识后重传。
- 超时、网络断开、HTTP 500 不证明上传没有提交。尤其提示“提交状态待确认”时，先按 accession 查询，不能自动重传；未收到自动生成标识时，由用户核对近期记录。
- 提交状态核对使用全局 accession 精确查询，省略专项、`orgType`、实际 taxId 和启用筛选，避免因筛选遗漏记录；这不同于把正常专项查询失败静默降级为全库。
- 上传成功目前是同步接口的最终响应，不是异步任务 ID；禁止重复点击提交，但不要宣称上传接口幂等。
- 不支持物理删除、替换序列、上传注释文件或原子批量启停；只展示现有或已完成扩展的操作。
- 该参考库不是 Kraken2、FastANI 等独立工具数据库的管理入口，不会触发它们的重建。
- 本轮不新增鉴权体系。当前接口应置于受控内部访问环境；前端隐藏按钮不等于后端授权。
